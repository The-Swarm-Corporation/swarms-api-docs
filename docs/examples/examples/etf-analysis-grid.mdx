## What This Example Shows

- The `BatchedGridWorkflow` endpoint, which pairs agent *i* with task *i* and runs the pairs in parallel
- A practical financial-analysis use case: two ETF analysts (risk + quant), each paired with one sector query (energy, semis)
- How to parse the per-loop, per-agent output

<Info>
`BatchedGridWorkflow` pairs agents and tasks by index: `agent_completions[i]` runs `tasks[i]`, so the two lists must be the same length, and `N` agents with `N` tasks make `N` runs, not `N × N`. To run every specialist on every ticker, send one entry per (specialist, ticker) pair, each with its own `agent_name`, since `outputs` is keyed by agent name.
</Info>

## Step 1: Setup

```python
import asyncio
import os
from typing import Any, Dict

import httpx
from dotenv import load_dotenv

load_dotenv()

API_KEY = os.getenv("SWARMS_API_KEY")
BASE_URL = "https://api.swarms.world"
ENDPOINT = f"{BASE_URL}/v1/batched-grid-workflow/completions"

HEADERS = {"x-api-key": API_KEY, "Content-Type": "application/json"}
```

## Step 2: Build the Grid

Two specialists, two tasks, two parallel runs: the Risk Analyst takes the energy task and the Quantitative Analyst takes the semiconductor task.

```python
def build_payload() -> Dict[str, Any]:
    return {
        "name": "ETF Analysis Grid",
        "description": "Risk and quant analysis across energy and semiconductor ETFs.",
        "max_loops": 1,
        "agent_completions": [
            {
                "agent_name": "Risk Analyst",
                "description": "Risk assessment and portfolio risk metrics.",
                "system_prompt": (
                    "You are a risk analyst specializing in ETF analysis. "
                    "Evaluate ETFs based on volatility, downside risk, correlation, "
                    "concentration risk, and risk-adjusted returns. Report Sharpe "
                    "ratio, maximum drawdown, beta, and Value at Risk (VaR)."
                ),
                "model_name": "gpt-4.1",
                "max_loops": 1,
                "temperature": 0.3,
            },
            {
                "agent_name": "Quantitative Analyst",
                "description": "Quantitative metrics and performance analysis.",
                "system_prompt": (
                    "You are a quantitative analyst specializing in ETF analysis. "
                    "Evaluate ETFs on performance, expense ratios, tracking error, "
                    "liquidity, and holdings composition. Provide returns, Sharpe "
                    "ratio, information ratio, and factor exposures."
                ),
                "model_name": "gpt-4.1",
                "max_loops": 1,
                "temperature": 0.3,
            },
        ],
        "tasks": [
            (
                "Analyze the top energy ETFs including XLE, VDE, and IYE. Provide "
                "detailed risk and performance metrics, holdings analysis, and "
                "investment considerations."
            ),
            (
                "Analyze the top semiconductor ETFs including SMH, SOXX, and XSD. "
                "Provide detailed risk and performance metrics, holdings analysis, "
                "and investment considerations."
            ),
        ],
    }
```

## Step 3: Call the Endpoint

The `/v1/batched-grid-workflow/completions` endpoint is async-friendly. Use `httpx.AsyncClient` to avoid blocking your event loop.

Equivalent raw request:

```bash
curl -X POST "https://api.swarms.world/v1/batched-grid-workflow/completions" \
  -H "x-api-key: $SWARMS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ETF Analysis Grid",
    "max_loops": 1,
    "agent_completions": [
      {"agent_name": "Risk Analyst", "model_name": "gpt-4.1", "system_prompt": "You are a risk analyst.", "max_loops": 1},
      {"agent_name": "Quantitative Analyst", "model_name": "gpt-4.1", "system_prompt": "You are a quantitative analyst.", "max_loops": 1}
    ],
    "tasks": [
      "Analyze the top energy ETFs including XLE, VDE, and IYE.",
      "Analyze the top semiconductor ETFs including SMH, SOXX, and XSD."
    ]
  }'
```

```python
async def run_grid() -> Dict[str, Any]:
    async with httpx.AsyncClient(timeout=300.0) as client:
        response = await client.post(ENDPOINT, headers=HEADERS, json=build_payload())
        response.raise_for_status()
        return response.json()
```

## Step 4: Parse the Output

`outputs` has one entry per loop (one here, since `max_loops` is 1). Each entry is a dict keyed by agent name, holding that agent's answer to its paired task.

```python
def show(response_data: Dict[str, Any]) -> None:
    for loop_idx, loop_outputs in enumerate(response_data.get("outputs", []), start=1):
        print("=" * 60)
        print(f"Loop {loop_idx}")
        print("=" * 60)
        if isinstance(loop_outputs, dict):
            for agent_name, agent_response in loop_outputs.items():
                print(f"\n--- {agent_name} ---")
                print(str(agent_response)[:400] + "...")


if __name__ == "__main__":
    response = asyncio.run(run_grid())
    show(response)
```

<Note>
Output shape: `outputs[loop_index][agent_name] = response`, where each agent's response answers the task at that agent's own index in `tasks`.
</Note>

## When To Use Batched Grid

| If you need… | Use |
| --- | --- |
| Each agent to see the previous agent's output | `SequentialWorkflow` |
| All agents to react to the same task in parallel | `ConcurrentWorkflow` |
| Each agent on its own task, all in parallel | **`BatchedGridWorkflow`** |
| A director to synthesize specialist opinions | `HierarchicalSwarm` |

Batched Grid is the right choice when each task is independent — no shared state, no inter-agent communication, just maximum parallelism.
