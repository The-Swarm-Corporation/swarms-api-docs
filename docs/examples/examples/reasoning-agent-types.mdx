Discover the different types of reasoning agents available in the Swarms API. The `/v1/reasoning-agent/types` endpoint provides information about specialized reasoning architectures designed for different problem-solving approaches.

<Warning>
**Premium Tier Required**: The `/v1/reasoning-agent/completions` endpoint is restricted to Pro, Ultra, and Premium plan subscribers. Free tier users will receive a 403 error. [Upgrade your account](https://swarms.world/platform/account) to access advanced reasoning capabilities.
</Warning>

<Info>
Reasoning agents use advanced techniques like self-consistency, majority voting, and iterative refinement to improve answer quality and reliability.
</Info>

## Reasoning Agent Type Comparison

The `/v1/reasoning-agent/types` endpoint currently returns 4 reasoning agent types:

| Type | Description | Best For | Samples | Quality Focus |
|------|-------------|----------|---------|---------------|
| **self-consistency** | Samples `num_samples` independent answers, then an aggregation agent reconciles them | High-stakes decisions | 3-5 | Consistency |
| **consistency-agent** | Alias for `self-consistency` | Same as `self-consistency` | 3-5 | Consistency |
| **ReflexionAgent** | Self-critiques and revises its own output across iterations (`max_loops`) | Tasks that benefit from self-correction | Ignored | Self-improvement |
| **AgentJudge** | Evaluates and scores candidate outputs over `max_loops` rounds | Output evaluation / grading | Ignored | Evaluation |

Any other `swarm_type`, including the removed `reasoning-duo`, `reasoning-agent`, `ire`, `ire-agent` and `GKPAgent`, returns `422` before any model call or charge.

## Request Parameters

Send these fields in the JSON body of `POST /v1/reasoning-agent/completions` (the `ReasoningAgentSpec` schema):

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `agent_name` | `string` | `"reasoning-agent"` | The unique name assigned to the reasoning agent |
| `description` | `string` | `"A reasoning agent that can answer questions and help with tasks."` | A detailed explanation of the reasoning agent's purpose and capabilities |
| `model_name` | `string` | `"claude-sonnet-5"` | The name of the AI model that the reasoning agent will utilize |
| `system_prompt` | `string` | `None` | The initial instruction or context provided to the reasoning agent |
| `max_loops` | `integer` | `1` | Maximum number of times the agent repeats its task. Between 1 and 50 |
| `swarm_type` | `string` | `"self-consistency"` | The reasoning agent type — pass one of the 4 values listed above |
| `num_samples` | `integer` | `1` | How many independent answers `self-consistency` and `consistency-agent` generate before aggregating. Between 1 and 2000; `0`, a negative value, `null` or anything above 2000 returns `422`. Ignored by `AgentJudge` and `ReflexionAgent` |
| `output_type` | `string` | `"dict-all-except-first"` | Accepted for schema compatibility but **ignored by the server** — responses are always returned in `dict-all-except-first` format |
| `memory_capacity` | `integer` | `None` | The memory capacity for a `ReflexionAgent` |
| `task` | `string` | `None` | The task to be completed by the reasoning agent |

<Note>
`self-consistency` and `consistency-agent` bill the prompt once per sample: input tokens are the counted prompt tokens × `num_samples`, so `num_samples: 5` costs about five times the prompt. `AgentJudge` and `ReflexionAgent` ignore `num_samples` and bill the tokens their internal agents used on every call. See [Billing](/docs/documentation/capabilities/reasoning_agent#billing).
</Note>

## Response Format

`POST /v1/reasoning-agent/completions` returns a `ReasoningAgentCompletionOutput` object:

| Field | Type | Description |
|-------|------|-------------|
| `job_id` | `string` | Unique identifier for the reasoning agent run |
| `status` | `string` | Status of the run, `"success"` on completion |
| `outputs` | `any` | The output generated by the reasoning agent — shape varies by reasoning type |
| `timestamp` | `string` | ISO-formatted timestamp of when the run was executed |
| `agent_name` | `string` | Name of the agent |
| `agent_type` | `string` | Type of the agent (the `swarm_type` used) |
| `agent_id` | `string` | Unique identifier for the agent instance |
| `usage` | `object` | Token usage: `input_tokens`, `output_tokens`, `total_tokens`, plus `total_cost` (the credits charged) and `flash_sale_applied` |

## Output Format

<Note>
The `output_type` request field is accepted by the schema but **ignored by the server** — the reasoning agent always runs with `dict-all-except-first`. For `self-consistency` and `consistency-agent`, `outputs` is a list of role/content entries: one holding the list of sample answers, then a `Majority Voting Agent` entry with the reconciled answer. `ReflexionAgent` and `AgentJudge` return a plain string. Passing `"dict"`, `"list"`, or `"final"` validates but has no effect on the response.
</Note>

```python
result = response.json()

# outputs is a list of role/content entries for most reasoning types
outputs = result["outputs"]
if isinstance(outputs, list):
    for entry in outputs:
        print(f"{entry.get('role', '')}: {entry.get('content', '')}")
else:
    # ReflexionAgent and AgentJudge return a plain string
    print(outputs)
```

## Best Practices

### Configuration Guidelines
1. **Task Complexity**: Match reasoning type to task complexity
2. **Sample Count**: Use more samples for high-stakes decisions
3. **Iteration Count**: Increase iterations for complex refinement
4. **Model Selection**: Choose appropriate model based on requirements

### Quality Assurance
1. **Consistency Checking**: Use self-consistency for critical decisions
2. **Self-Correction**: Use ReflexionAgent for drafts that improve with revision
3. **Evaluation**: Use AgentJudge to grade another agent's answer
4. **Validation**: Always validate reasoning outputs

### Performance Considerations
1. **Resource Usage**: Monitor token usage and costs
2. **Response Time**: Balance quality with response speed
3. **Scalability**: Consider parallel processing for multiple tasks
4. **Caching**: Cache reasoning results when appropriate

### Error Handling
1. **Fallback Logic**: Implement fallback to simpler reasoning types
2. **Timeout Handling**: Set appropriate timeouts for long-running tasks
3. **Result Validation**: Validate reasoning outputs for correctness
4. **Logging**: Log reasoning processes for debugging
