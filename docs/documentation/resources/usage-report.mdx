<Info>
There is no dedicated endpoint that returns a historical, day-by-day breakdown of your spend. Instead, the Swarms API exposes three complementary pieces: the **current pricing model** (`/v1/usage/costs`), your **raw request logs** (`/v1/account/logs`), and an **at-a-glance metrics summary** (`/v1/account/metrics/summary`). Combine these client-side for a custom usage report — see each section below.
</Info>

The Usage endpoint returns the flat fees the API charges (per-agent, image and search), the fallback token rates for models with no price data, and the night-time discount. Tokens are billed at each model's own price plus a 15% service fee, so per-model token prices are not in this response: get them from `GET /v1/models/available` or `GET /v1/models/pricing?model_name=...`. Use both to compute expected costs before you run a request, or to keep your own cost estimates in sync with the live pricing. See [Pricing](/docs/documentation/resources/pricing) for how a charge is calculated.

## Endpoint Information

- **URL**: `/v1/usage/costs`
- **Method**: `GET`
- **Authentication**: Required (`x-api-key` header)
- **Rate Limiting**: Subject to tier-based rate limits

---

## Query Parameters

None. This endpoint always returns the current pricing model in effect.

## Code Examples

<Tabs>
  <Tab title="Python">
    ```python
    import os
    import requests
    from dotenv import load_dotenv

    load_dotenv()

    API_KEY = os.getenv("SWARMS_API_KEY")
    BASE_URL = "https://api.swarms.world"

    headers = {
        "x-api-key": API_KEY,
        "Content-Type": "application/json",
    }

    response = requests.get(f"{BASE_URL}/v1/usage/costs", headers=headers)
    data = response.json()

    pricing = data["usage_pricing"]
    print(f"Per-agent fee (swarms and workflows): ${pricing['swarm_completions_agent_cost']}")
    print(f"Fallback input rate (unpriced models): ${pricing['fallback_input_cost_per_1m']} / 1M tokens")
    print(f"Fallback output rate (unpriced models): ${pricing['fallback_output_cost_per_1m']} / 1M tokens")
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import "dotenv/config";

    const API_KEY = process.env.SWARMS_API_KEY;
    const BASE_URL = "https://api.swarms.world";

    if (!API_KEY) {
      throw new Error("SWARMS_API_KEY is not set");
    }

      headers: {
        "x-api-key": API_KEY,

      },
    });

    if (!res.ok) {
      throw new Error(`HTTP ${res.status}: ${await res.text()}`);
    }

    const data = await res.json();
    console.log(data.usage_pricing);
    ```

## Response Schema

### PricingDetailsOutput Object

| Field | Type | Description |
|---|---|---|
| `usage_pricing` | `object` | Flat fees, fallback token rates and the night-time discount. Per-model token prices come from `GET /v1/models/available` |
| `timestamp` | `string` | ISO timestamp when the pricing information was retrieved |

### usage_pricing Object

| Field | Type | Description |
|---|---|---|
| `fallback_input_cost_per_1m` | `number` | Cost per 1M input tokens (USD) for a model with no price data, before the 15% service fee. Not the price of most models |
| `fallback_output_cost_per_1m` | `number` | Cost per 1M output tokens (USD) for a model with no price data, before the 15% service fee. Not the price of most models |
| `swarm_completions_agent_cost` | `number` | Cost per agent in the request for swarm completions, graph workflow and batched grid workflow (USD) |
| `agent_completions_img_cost` | `number` | Cost per image for agent completions (USD) |
| `search_cost` | `number` | Cost per agent completion request that enables `auto_search`, however many searches run (USD) |
| `night_time_discount` | `number` | Discount multiplier applied to swarm completion token costs, 8 PM - 6 AM PT (0.5 = 50% off) |

<Note>
MCP servers and the `web_scraper` tool have no fee of their own; only the tokens are billed. The old `swarm_completions_*_cost_per_1m`, `agent_completions_*_cost_per_1m`, `agent_completions_mcp_cost` and `scrape_cost` fields are no longer returned.
</Note>

### Example Response

```json
{
  "usage_pricing": {
    "fallback_input_cost_per_1m": 6.5,
    "fallback_output_cost_per_1m": 18.5,
    "swarm_completions_agent_cost": 0.01,
    "agent_completions_img_cost": 0.25,
    "search_cost": 0.04,
    "night_time_discount": 0.5
  },
  "timestamp": "2026-10-12T19:01:46.180153+00:00"
}
```

|---|---|

## Request Logs

`GET /v1/account/logs` returns your account's completion records, newest first, across all of your API keys (including revoked ones), excluding client IP information. GET requests and failed requests have no completion record, so they do not appear. `logs` holds at most the 1000 newest records.

<Note>
`GET /v1/swarm/logs` is a **deprecated alias** for the same endpoint, kept only for backwards compatibility. Use `/v1/account/logs` in new integrations.
</Note>

```bash
curl -H "x-api-key: $SWARMS_API_KEY" \
     https://api.swarms.world/v1/account/logs
```

### SwarmLogsOutput Object

| Field | Type | Description |
|---|---|---|
| `status` | `string` | Status of the request |
| `count` | `integer` | Exact total number of matching log entries across every API key on the account, including revoked ones. This is **not** `len(logs)` — `logs` is capped at the 1000 newest entries, so `count` exceeds it once your account passes 1000 requests |
| `logs` | `array` | Log entries with timestamps, endpoints, and status (capped at the 1000 newest) |
| `timestamp` | `string` | ISO timestamp when the response was generated |

```json
{
  "status": "success",
  "count": 1284,
  "logs": [
    {
      "endpoint": "/v1/agent/completions",
      "status": "success",
      "timestamp": "2026-09-14T09:12:03+00:00"
    }
  ],
  "timestamp": "2026-09-14T12:00:00+00:00"
}
```

## Metrics Summary

`GET /v1/account/metrics/summary` returns an at-a-glance overview of your core usage metrics across all of your API keys.

<Note>
`GET /v1/metrics/summary` is a **deprecated alias** for the same endpoint, kept only for backwards compatibility. Use `/v1/account/metrics/summary` in new integrations.
</Note>

```bash
curl -H "x-api-key: $SWARMS_API_KEY" \
     https://api.swarms.world/v1/account/metrics/summary
```

### MetricsSummaryOutput Object

| Field | Type | Description |
|---|---|---|
| `success` | `boolean` | Whether the summary was retrieved successfully |
| `unique_agents` | `integer` | Number of unique agent configurations you've used |
| `total_completion_calls` | `integer` | Lifetime count of completion calls |
| `successful_completions` | `integer` | Lifetime count of completions with status `success` |
| `completions_last_24h` | `integer` | Completion calls in the last 24 hours |
| `completions_last_7d` | `integer` | Completion calls in the last 7 days |
| `timestamp` | `string` | ISO timestamp when the summary was generated |

```json
{
  "success": true,
  "unique_agents": 14,
  "total_completion_calls": 1284,
  "successful_completions": 1259,
  "completions_last_24h": 37,
  "completions_last_7d": 214,
  "timestamp": "2026-09-14T12:00:00+00:00"
}
```

## Related Endpoints

For other account-level usage and spend tracking, use:

| Need | Endpoint | Returns |
|---|---|---|
| Current credit balance | `GET /v1/account/credits` | `credit`, `free_credit`, `referral_credits`, `total_credits` |
| Current rate limit usage | `GET /v1/rate/limits` | Requests used/remaining per minute, hour, and day |

<Note>
Billable completion endpoints require your `total_credits` balance to be above \$1.00. This is checked before the request runs — if the balance is at or below the minimum, the API returns a **402 Payment Required** error without doing any work. Use `GET /v1/account/credits` to monitor your balance.
</Note>
