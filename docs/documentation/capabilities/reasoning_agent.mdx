title: 'Reasoning Agent Completions'
description: 'Execute reasoning agents with specialized cognitive architectures — self-consistency, Reflexion and an agent judge — via /v1/reasoning-agent/completions'
---

The Reasoning Agent Completions endpoint (`/v1/reasoning-agent/completions`) runs a single task through a specialized reasoning architecture rather than a plain agent loop. Instead of one model call producing one answer, a reasoning agent decomposes, samples, critiques, or debates its way to a result — trading cost and latency for reliability on problems where a single pass is often wrong.

<Warning>
**Premium tier required.** This endpoint is restricted to Pro, Ultra, and Premium subscribers. Free-tier keys receive a `403` with upgrade instructions. See [Premium Endpoints](/docs/documentation/resources/premium-endpoints).
</Warning>

## Endpoint

| Property | Value |
|----------|-------|
| **Method** | `POST` |
| **Path** | `/v1/reasoning-agent/completions` |
| **Base URL** | `https://api.swarms.world` |
| **Authentication** | `x-api-key` header (required) |
| **Tier** | Pro, Ultra, Premium |

## Architecture

```mermaid
flowchart LR
    T["Task"] --> A["Reasoning architecture"]
    A --> S1["Pass 1"]
    A --> S2["Pass 2"]
    A --> S3["Pass 3"]
    S1 --> R["Reconciled answer"]
    S2 --> R
    S3 --> R
```

The exact internals depend on `swarm_type` — some architectures sample independently and reconcile, others critique and revise in sequence. What they share is that one request produces multiple internal reasoning passes before returning.

## ReasoningAgentSpec

The request body is a single `ReasoningAgentSpec` object.

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `task` | `string` | No* | `null` | The task to be completed by the reasoning agent. Not enforced by the schema, but a missing or blank `task` returns `400` before anything runs — always send it |
| `agent_name` | `string` | No | `"reasoning-agent"` | Unique name assigned to the reasoning agent |
| `description` | `string` | No | `"A reasoning agent that can answer questions and help with tasks."` | Explanation of the agent's purpose and capabilities |
| `model_name` | `string` | No | `"claude-sonnet-5"` | The AI model backing the reasoning agent |
| `system_prompt` | `string` | No | `null` | Initial instruction or context provided to the agent |
| `max_loops` | `integer` | No | `1` | Maximum times the agent repeats its task. Between 1 and 50 |
| `swarm_type` | `string` | No | `"self-consistency"` | The reasoning architecture to use — see [Reasoning Types](#reasoning-types) |
| `num_samples` | `integer` | No | `1` | How many independent answers `self-consistency` and `consistency-agent` generate before aggregating. Between 1 and 2000; `0`, a negative value, `null` or anything above 2000 returns `422`. Ignored by `AgentJudge` and `ReflexionAgent` |
| `output_type` | `string` | No | `"dict-all-except-first"` | Accepted but ignored — see [Output Types](#output-types) |
| `memory_capacity` | `integer` | No | `null` | Memory capacity for a `ReflexionAgent` |

### Reasoning Types

`swarm_type` accepts the following values:

| Value | Description |
|-------|-------------|
| `self-consistency` | Samples `num_samples` independent answers in parallel, then an aggregation agent reconciles them into one result |
| `consistency-agent` | Alias for `self-consistency` |
| `ReflexionAgent` | Attempts the task, evaluates its own output, and revises using a short/long-term memory of prior attempts. `max_loops` is the number of reflection iterations |
| `AgentJudge` | Reviews and critiques a candidate output rather than generating a fresh answer from scratch. `max_loops` is the number of evaluation rounds |

<Note>
Any other value, including the removed `reasoning-duo`, `reasoning-agent`, `ire`, `ire-agent` and `GKPAgent`, returns `422` before any model call or charge. Call [`GET /v1/reasoning-agent/types`](/docs/examples/examples/reasoning-agent-types) for the live list.
</Note>

### Output Types

`output_type` is accepted for schema compatibility but **ignored by the server**: every run returns `outputs` in `dict-all-except-first` format. The field still validates against `list`, `dict`, `dictionary`, `string`, `str`, `final`, `last`, `json`, `all`, `yaml`, `dict-all-except-first`, `str-all-except-first`, `dict-final` and `list-final`; any other value returns `422`.

## Quick Start

<Tabs>
  <Tab title="Python">
    ```python
    import os
    import json
    import requests
    from dotenv import load_dotenv

    load_dotenv()

    API_KEY = os.getenv("SWARMS_API_KEY")
    BASE_URL = "https://api.swarms.world"

    headers = {
        "x-api-key": API_KEY,
        "Content-Type": "application/json",
    }

    payload = {
        "agent_name": "Valuation Reasoner",
        "description": "Works through multi-step valuation problems",
        "model_name": "claude-sonnet-5",
        "swarm_type": "self-consistency",
        "num_samples": 3,
        "max_loops": 1,
        "task": (
            "A SaaS company has $12M ARR growing 40% YoY, 80% gross margin, "
            "and burns $500K/month. At a 6x forward revenue multiple, what is "
            "the implied valuation, and how many months of runway remain on a "
            "$20M cash balance? Show your reasoning."
        ),
    }

    def run_reasoning_agent() -> dict | None:
        resp = requests.post(
            f"{BASE_URL}/v1/reasoning-agent/completions",
            headers=headers,
            json=payload,
            timeout=600,
        )

        if resp.status_code == 200:
            return resp.json()

        print(f"Error: {resp.status_code} - {resp.text}")
        return None

    if __name__ == "__main__":
        data = run_reasoning_agent()
        if data:
            print(f"✅ Job {data['job_id']} ({data['agent_type']})")
            print(json.dumps(data["outputs"], indent=2))
            print(f"Tokens: {data['usage'].get('total_tokens')}")
    ```

### Response Schema

| Field | Type | Description |
|-------|------|-------------|
| `job_id` | `string` | Unique identifier for the reasoning agent run |
| `status` | `string` | Status of the run. Defaults to `"success"` |
| `outputs` | `any` | The generated output. **Shape varies by reasoning type** |
| `timestamp` | `string` | ISO-formatted timestamp of when the run executed |
| `agent_name` | `string` | Name of the agent |
| `agent_type` | `string` | The reasoning architecture that ran (the `swarm_type`) |
| `agent_id` | `string` | Unique identifier for the agent instance |
| `usage` | `object` | `input_tokens`, `output_tokens`, `total_tokens` (integers, the billed totals), `total_cost` (a float — the credits charged for this run) and `flash_sale_applied` (boolean) |

<Warning>
`outputs` is deliberately untyped in the schema: each reasoning type returns a different structure. `self-consistency` and `consistency-agent` return a list of role/content entries: one whose `content` is the list of sample answers, then a `Majority Voting Agent` entry holding the reconciled answer. `ReflexionAgent` returns its best answer across iterations, and `AgentJudge` returns its conversation (your task followed by each evaluation round), both as strings. Do not assume a fixed shape — branch on `agent_type`.
</Warning>

### Status Codes

| Code | Meaning |
|------|---------|
| `200` | Completion returned successfully |
| `400` | Missing or blank `task`, an Ollama or Hugging Face `model_name`, or a prompt over your tier's token limit |
| `401` | Missing, unknown or revoked API key |
| `402` | Credit balance at or below $1.00 |
| `403` | Free tier — premium subscription required |
| `404` | `model_name` is not a model the API serves |
| `422` | Malformed request body (e.g. invalid `swarm_type`, `num_samples` outside 1–2000, or `max_loops` outside 1–50) |
| `429` | Rate limit exceeded |
| `500` | The reasoning agent failed while running |

<Note>
This endpoint is both premium-only and billable, so a request is checked, in order, for: API key presence (401), API key validity (401), credit balance (402), and premium tier (403) — all before the reasoning agent runs. Every error from this pre-flight check is returned in the shape `{"error": {"type": ..., "message": ..., "detail": ..., "status_code": ...}}`.
</Note>

## When to Use a Reasoning Agent

Reasoning agents cost more than a plain agent call — multiple internal passes means multiple sets of billed tokens. They earn that cost on problems where a single pass is unreliable:

| Use it for | Use a plain agent for |
|------------|----------------------|
| Multi-step quantitative problems where an arithmetic slip invalidates the answer | Summarization, extraction, rewriting |
| Questions with a verifiable right answer worth double-checking | Open-ended generation with no single correct output |
| High-stakes classification where a wrong call is expensive | High-volume, low-stakes classification |
| Problems where you want the reasoning trace as an artifact | Cases where only the final text matters |

Raise `num_samples` to increase consensus strength on `self-consistency`; raise `max_loops` to give `ReflexionAgent` more revision rounds. Both raise the cost.

### Billing

Tokens are billed at the model's per-token price, with no per-agent fee and no night-time discount. How the tokens are counted depends on the type:

- **`self-consistency` and `consistency-agent`** bill the prompt (`agent_name`, `description`, `system_prompt` and `task`) once per sample, so input tokens are the counted prompt tokens × `num_samples`, and `num_samples: 5` costs about five times the prompt. Output tokens are counted from the returned `outputs`.
- **`AgentJudge` and `ReflexionAgent`** bill the tokens their internal agents reported for every call they made. A `ReflexionAgent` calls its actor, evaluator and reflector on each iteration, so a higher `max_loops` bills more tokens.

`usage` reports the billed totals.
